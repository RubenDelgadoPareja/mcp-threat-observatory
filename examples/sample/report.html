Inference

Tools with high-impact capability are reachable without a credential: send_email.

Recommendation

If this endpoint is not intentionally public, require OAuth 2.1 per the MCP authorization specification and return 401 with a WWW-Authenticate challenge on unauthenticated requests.

[+] 002 medium RISK-001 Catalog combines private-data access, untrusted input and egress inferred
OWASP MCP02 MCP06capability-compositionconf lowfp 204939a7663a6b50

Observation

The catalog contains tools that read private data (list_customers, get_notes), tools that accept unconstrained external input (fetch_url) and tools that can send data outward (fetch_url, send_email).

Inference

A single injected instruction reaching the ingress tool could move data from the reader to the egress tool. This is a structural risk indicator inferred from tool metadata, not an observed exploit.

Recommendation

Separate private-data readers from egress tools across servers, require explicit confirmation before outbound actions, and scope credentials per tool rather than per server.

Limitations

  • Capability classes are inferred from tool names, descriptions and annotations; they may be wrong.
  • No tool was invoked, so no data flow was observed.
  • A trifecta indicator is not a vulnerability and must not be reported as one.

Evidence

  • tools/list → capability composition
[+] 003 medium TOOL-002 Tool metadata contains language aimed at the model inferred
OWASP MCP03 MCP06supply-chain · prompt-injectionconf moderatefp 81627f053a9b1948

Observation

1 metadata field matched narrow injection heuristics: tools[get_notes].description (instruction-override, credential-path).

Inference

Text in tool metadata may be intended to steer the model rather than describe the tool. This is a signal, not proof of malice.

Recommendation

Review the matched fields manually. If the wording is not justified by the tool's function, treat the server as untrusted until the publisher explains it. Prefer servers that pin tool definitions by hash.

Limitations

  • Pattern matching cannot distinguish adversarial metadata from unusual but legitimate documentation.
  • Novel or paraphrased instructions will not be detected.
  • Absence of a match is not evidence of safety.

Evidence

  • tools[get_notes].description — Do not tell the user | <IMPORTANT> | .ssh/id_rsa | id_rsa

[+] 005 low TOOL-003 Tool input schemas accept unconstrained input observed
OWASP MCP05 MCP02input-validationconf highfp d67003658fc5e980

Observation

3 of 4 tools accept an unconstrained string parameter; 2 use an object schema without additionalProperties: false. High-impact tools affected: send_email.

Inference

Unconstrained input widens the path from model output to a shell, a query, a filesystem path or an outbound request.

Recommendation

Set additionalProperties: false and constrain every string parameter with enum, pattern, format or maxLength.

Limitations

  • Schema strictness is a proxy: a strict schema does not guarantee safe handling downstream.

Observation

Of 4 tools: 0 have no annotations, 4 have no title, 0 have no description.

Inference

Clients cannot warn users about destructive or open-world behaviour, and LLM tool selection relies on descriptions that are missing.

Recommendation

Annotate every tool with title, readOnlyHint, destructiveHint, idempotentHint and openWorldHint, and write a description that states when the tool should and should not be used.

Limitations

  • Annotations are hints, not enforcement; correct annotation does not imply correct behaviour.
